OUR STRENGTHS

优势是完整体验的组合。

衣间的核心定位可以表述为：一位记得你的穿衣习惯、从真实衣橱出发、能持续聊下去的穿搭伙伴。

01 / 产品差异

把“知道我”做成用户能感知的体验

六角色、可调相处方式、穿搭手记、天气与来信形成统一接触面。用户能主动决定和谁聊、怎么聊，以及哪些偏好被保存。

优势已体现在功能组合；情感认同、次日回访与满意度仍需用户验证。
02 / 使用价值

从已有衣服出发，降低搭配门槛

默认个人衣橱、部分匹配也可交付，再用对话继续调整。真实衣物、文字参考与收费试穿分开呈现，用户更容易理解手里有什么、下一步能做什么。

这是面向个人衣橱日常使用的优势；库存检索上限同时限制了覆盖能力。
03 / 工程取舍

业务边界集中，更便于定位与验证

一个主Agent、明确任务和少量接口；本项目状态与旧业务数据域分离。硬条件与费用确认由程序约束，人物表达可以独立迭代。

这是结构上的可控性判断；并不等于已证明调用更少、延迟更低或故障更少。
最需要正视的短板：常规衣橱检索只读最多150件，并非全库存语义搜索；缺少候选手选与商品编辑闭环。六角色已有真实文字定向复测，但辨识度仍有观察项，签到仍是刷新即清空的演示。漂亮界面不能替代选得对与用得稳。S07V02S03

SCENE 01

“我喜欢短袖和衬衫，不喜欢黄色、绿色。”

衣间的当前链路

只分享喜好时不选款，可按当前规则保存本人明确稳定的穿搭偏好，并生成真实保存回执。

同级 Agent 的当前链路

当前显式记忆策略要求记住/保存等控制指令；普通偏好陈述不能直接算自动长期记忆。

SCENE 02

“这双鞋换一双，我想自己挑。”

衣间的当前链路

可用文字局部替换并冻结其余衣物；现有单品详情可查看，但没有等价可搜索候选换款器。

同级 Agent 的当前链路

可浏览当前槽位候选、进一步筛选并提交所选商品，受来源/类别/版本约束。

SCENE 03

“衣橱只有一件合适的，本周怎么穿？”

衣间的当前链路

可展示真实匹配部分、缺项文字参考，并按本周日期边界安排；不把缺项生成成自有单品。

同级 Agent 的当前链路

有缺口扩展来源、手选和修复路径；未见同等部分交付+逐日周计划的一体输出。

SCENE 04

“刚上传的这件分类错了，顺便改价格。”

衣间的当前链路

上传及用单品继续搭配已接入，属性修正仍需沿用App编辑流程。

同级 Agent 的当前链路

有属性预览、变更清单、明确确认及权威读回；上传后修正可续接原搭配任务。

先验证

建立同题、同库存的对照基线

优先补齐

个人衣橱检索 + 手选换款

先解决150件常规候选上限、定向召回和用户自己挑选；继续保持个人衣橱范围。

随后评估
