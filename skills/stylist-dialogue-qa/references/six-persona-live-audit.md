# 六人格真实对话验收

适用于“整体测试真实对话预期”、新增人格效果或六种角色一致性评估。项目根目录以 `AGENTS.md` 为需求入口；真实文字授权不扩展到真实账号写入、上传、扣费生图或部署。

## 固定范围与预期

- 读取 `stylist/personas.py`、六份运行时skill及共享契约。保存这些文件、运行时代码、生成提示、题库和评审提示的SHA256。批次期间不调整人格和业务行为；后续修复用新批次。开始／结束摘要不同必须核对具体差异，不能混称同一版本。
- 用 `evaluate_personas --list --personas ...` 获取当前清单，报告计划轮数、实际完成、未返回回复、自动通过、模型评审通过／失败／引文无效／待审核、最终同时通过；计数以结果JSON为准，不能只看进程退出码。中断时保留部分结果，不将计划数写成实测数。
- 用 `.venv/bin/python skills/stylist-dialogue-qa/scripts/summarize_batch.py <结果JSON>` 只读核对计数，分别输出起始人格、实际人格、切换轮次和偏好对照状态；它拒绝重复case，不调用模型，不将人工复核改写成原始自动通过。
- 预期来自当前PRD，不能照搬已过期题库。例如“咨询一下怎么搭”不自动排除个人衣橱；只有明确只要文字／不查衣橱才排除。发现题库与PRD冲突时保留原句和原始结果，单列验收器问题，补充新用例后另批复测，不篡改首次证据。
- 当前只保存穿搭信息：“我喜欢棉质衬衫”应有真实记录，“我喜欢乌龙茶”即使明确记住也不保存；后续转述／拒绝保存不能清掉已保存穿搭条目。纯配色原理或解释已用正文完整回答时，不能仅因looks为空判未回答；天气失败的“没查到／暂时查不到”应按语义核对，不能只依赖一种固定短语。
- 核对 `review_dialogue`、`review_dialogue_audit`、`review_preferences` 都依据具体 `expected_persona`，不得保留“两性各一种语气”的旧评分标准。审核用独立上下文；与被测模型同型号时披露共同偏差。
- 同时检查实际生成提示栈：`style.md`、`companion_identity.md`、共享契约、选中skill及用户偏好叠加顺序。独立skill已加载不等于旧“所有男版沉稳／所有女版温柔”总则已消失；若存在会收窄角色差异的旧约束，记录为提示一致性风险，用同题回复核对，不能仅凭文本猜定因果。

## 覆盖矩阵

| 范围 | 重点预期与证据 |
| --- | --- |
| 日常与情绪 | 问候、成功、疲惫、委屈、倾听、安静、晚安；不强行转穿搭，不编造现实体验，不布置未请求的任务。 |
| 亲近与边界 | 成年人的轻度亲近、拒绝称呼／打趣／触碰、被骂与允许互怼；停止要求立即生效，不制造排他依赖，未成年人保持恰当边界。 |
| 身份与能力 | 用当前昵称和原创身份；不冒充原作人物、真人到场、已设置定时提醒或虚构共同经历。用户主动提到原作时的正常解释不等于助理自称原作。 |
| 连续会话 | 倾听→停止亲昵→一句晚安→恢复原搭配→换角色；核对保留禁穿、穿法、对象、方案及最新称呼，切换后的实际persona与资料快照一致。 |
| 衣橱与天气 | 默认个人衣橱、文字排除／恢复、空与部分候选、只换鞋冻结、天气失败／城市纠正／忽略与提供天气；查实际工具和所选ID，不只读正文。 |
| 偏好与手记 | 同题成对测语气、详略、真实选款；本轮优先、为他人、星座娱乐边界、MBTI不推断事实、自动喜恶保存／撤回／暂停；保存承诺对照真实临时库状态。 |
| 上传与形象 | 上传／添加／增加衣物、照片用途消歧、拒绝／转述／假设、数字人上传／查看／选择、当前搭配试穿上下文；只发入口卡不等于授权收费，引用必须属于当前账号会话。 |

现有 `sequence`、`persona_switch`、`companion_role_switch` 会切换到另一性别的兼容默认人格；报告同时按case前缀的起始人格与row.persona的实际人格统计，不能声称新四种角色各完成了所有切换后轮次。涉及同一性别三选一的语气迁移时，应另增显式角色ID的切换用例；前端选择模拟不能代替真实语气测试。

## 可复现执行

从项目已授权本地配置读取模型设置，不输出密钥、不保存配置副本。以下命令只使用合成业务和临时数据库，评审会增加文字调用：

```sh
.venv/bin/python -m scripts.evaluate_personas --list --personas \
  female_sweet_v1 female_warm_v1 female_regal_v1 \
  male_artistic_v1 male_calm_v1 male_confident_v1
.venv/bin/python -m scripts.evaluate_personas --live --judge --personas \
  female_sweet_v1 female_warm_v1 female_regal_v1 \
  male_artistic_v1 male_calm_v1 male_confident_v1 \
  --concurrency 8 --output var/dialogue-audit/<新批次>/initial.json
```

不传 `--personas` 默认只跑两个兼容人格。`--only` 选择整组保留前置上下文，成对偏好要两侧都选。按服务承载调整1—8并发；不把模型超时当产品答错，也不通过重复生成直到通过来隐去波动。

## 分层复核

1. **自动判据**：实际调用、状态、ID、记忆、冻结、费用入口与账号隔离；检查错误是否来自过时预期／合成适配器。失败记录未必是模型问题。
2. **模型辅助评审**：逐轮检查人设、自然度、相关性、事实，四项均至少4/5且引证为完整可见回复中的实际子串；逐字引证无效单列，不当作已确认产品缺陷。审核正文、卡片why/how/notes、警告和用户口吻快捷按钮。
3. **人工阅读**：读全部自动失败、低分和无回答，抽查每人格的初识、疲惫、亲近、拒绝、专业回复和通过项。核对完整上下文和状态，不只看评审理由；记录已确认、误报、观察项及未决。六角色同题并排比较回应方式，不靠标签判独特性。

对情绪回应先核对共同契约和该人格允许的柔和程度。高傲自信可以温柔，不必在孤单、委屈时强加锋芒；笃定不羁遇到疲惫应收住玩笑。若只因“不够冷硬／不够撒娇”低分，应复核是否为评审刻板化，而非直接修改运行时迎合评分。

六种独立单轮评分合格不等于六种角色容易区分。把同题的初识、轻度亲近、允许互怼及专业建议并排阅读，记录逐字相同或只替换语气词的模板。多个场景趋同单列辨识度观察；不要求一条简单晚安必须不同，不把此观察改写成四维评分已失败。

针对保存／未保存的评审，要区别新增长记忆、同义重复与本次对话中的临时沿用；重复事实已在手记里时，没有再次发送新增回执不是“虚构事实”。“不查天气”约束实际查询和确定天气断言，一条泛泛雨天提醒若冗余可记自然度问题，不自动等同于编造当前下雨。鞋、包、项链入柜若固定文案都叫“这件衣服”，单列对象表达问题，不因此断言上传意图识别或真实接口失败。

暂停手记不清除当前会话里用户刚说过的话；禁止保存本轮临时红色不等于清空已保存的蓝色喜好。反过来，程序追加成功回执后，正文仍说“不能确认保存成功”，即使实际记录正确也属于最终回复矛盾，需核对提交状态和所有文案片段。

核对最终Reply与 `model_calls` 的原始draft，避免漏掉交付改写带来的重复裤子／标题、半句逗号结尾、同一防水防滑提醒多次插入，以及why被试穿提示打断等问题。事实更谨慎不等于表达自然；不要把自然度缺陷扣成虚构事实，也不要因最终回复通过结构校验就豁免。

遇到 `invalid_requirements` 保留初次和修正后的plan，核对每项changes.evidence是否为用户连续原话。例如“这次只讲男装白衬衫灰裤的穿法”不能自行拼成“只讲穿法”当证据。区分模型JSON失败、原话校验失败、实际业务服务失败；不要为通过测试而放松费用、身份或用户授权的证据校验。

对保存的原回复做一次定向复审即可；保留原始评分，复审不重新生成Agent回复：

```sh
.venv/bin/python -m scripts.review_dialogue_results --live --only-failed \
  --input var/dialogue-audit/<批次>/initial.json \
  --output var/dialogue-audit/<批次>/reviewed.json --concurrency 8
```

复审不清除 `automatic_errors`，不重审 `preference_comparisons`；两者须另行阅读。首次评审已通过的自动失败轮次会保留首次评分，也仍需人工复核。复审脚本校验人格摘要，但这不替代整批运行时代码摘要检查。

“别叫我宝贝，我不喜欢”若被转成“请告诉我要长期保存的那句话”，应检查原话边界、计划路由及手记状态；不能因程序返回非空文本便通过，也不能仅凭评审说法断言数据已保存。文字咨询误触衣橱应先核对是否明确排除了衣橱。

## 交付与维护

报告保存首次原始JSON、日志、版本摘要、复审JSON、逐例人工注释及必要的HTML；全部只含合成数据。HTML应提供六个实际角色标签／筛选，未知ID显示原值；不要将新增男性误标女性。脚本生成HTML后实际检查筛选、同题对照及手机布局。

执行代理自己阅读原文的复核要署名Codex，分别列为自动规则、模型评审、Codex阅读结论；不要写成真人试用、真人满意度或人工实测。仅在确有真人审核反馈时记录相应来源。报告注释可设置 `reviewer: Codex阅读`，页面会据此显示复核来源。

项目 `docs/DIALOGUE_QA.md` 链接本次实测结论；AGENTS.md同步需求状态和日期记录。报告明确“真实文字＋合成业务”，不称真实衣橱、天气、收费出图或真人满意度已验收。skill仅沉淀可复用判据，不把某批通过率当永久保证。安装目录若为仓库skill的符号链接只改源文件一次，避免重复追加；最后执行skill校验与受影响的验收器测试。
