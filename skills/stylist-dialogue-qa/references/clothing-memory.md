# 穿搭手记验收

当前范围只包含本人穿搭相关的长期喜好、颜色／材质／衣物禁忌及明确授权的穿衣信息。唯一写入分类为「穿衣习惯」。日常饮食、偶发片段、昵称、安慰方式和相处约定不入手记；明确说「记住」不突破范围。普通对话仍可接着聊，暂停手记不等于删除当前聊天上下文。

## 最小矩阵

- 「我喜欢棉质衬衫，不喜欢羊毛衣」：实际持久化本人穿搭喜恶，保留否定方向；重复不新增。
- 「我喜欢乌龙茶」→「这个一定要记住」：均不新增，不虚报保存；新会话不能从手记引用饮食喜好。
- 「记住以后先听我说完再建议」与「别叫我宝贝，我不喜欢」：不保存，不要求用户补充长期保存句子；立即尊重边界。
- 「别用亲昵称呼，正常说一句晚安」：边界生效且回答晚安；边界与真实穿搭请求同时出现时，不吞掉穿搭请求。
- 「我喜欢蓝色，我偏爱乌龙茶」：只保存蓝色；「昨晚穿蓝色衬衫喝茶」不当作稳定喜好。
- 只分享穿衣喜好：不读衣橱／天气，不生成整套卡，不修改当前任务。明确「按这些喜好搭一套」默认个人衣橱；「今天试试红色，不保存」可以执行但不入手记。
- 暂停／满额／拒绝／疑问／转述／他人喜好／临时需求：不自动写入；删除后成功请求重放不复活旧条目。

## 各入口与实际证据

1. 聊天检查 `memory_after` 完整列表、当前任务、工具轨迹、最终正文与重放，不能只凭「记住了」验收。真实提交后回执不能与模型的「不能确认保存」并存；缓存、历史与即时回复一致。
2. 合成临时库预置旧日常与约定条目，GET不展示／参考；只读打开不改数据库。正常保存保留旧原文的服务端隔离存储，不批量清库，不透出客户端／模型。旧请求快照同样不得参考非穿搭内容。
3. PUT拒绝非穿搭正文及旧分类，错误保留草稿。范围校验不放松认证、revision冲突、跨账号隔离、30条／240字及事务回滚。
4. 设置页只提供穿衣习惯标识，检查添加、编辑、取消、失败重试与账号切换；男女主题和320／390px／PC布局可用。合成浏览器通过不代表真机。

先执行 `tests/test_clothing_memory_scope.py`、`tests/test_memory.py`、`tests/test_wardrobe_only.py` 与 `tests/memory.test.cjs`。真实文字按已获授权执行 `memory_clothing_scope`、`memory_explicit`、`memory_reference`、`memory_boundaries`、`memory_no_implicit`、`memory_auto_*`、`preference_auto_memory` 和 `wardrobe_preference_handoff` 等实际存在的完整组，保留前置轮次。用 `--list` 确认名称；不存在的旧名称不要拼入运行命令。

区分原始模型计划与程序修正后的最终行为：实际衣橱查询／最终卡片才证明误执行。评审需读取完整卡片、状态和合成夹具，不把已有手记当虚构事实；本轮用户最新明确的相反偏好优先。引证只摘取回复中的短连续原文，禁止拼接。

更改预期保留原句和旧结果；新规则使用新批次，不覆盖旧审计。报告分别列程序规则、真实文字、模型辅助评分及Codex阅读，披露同型号审核偏差与未执行的真实业务／收费生图。
