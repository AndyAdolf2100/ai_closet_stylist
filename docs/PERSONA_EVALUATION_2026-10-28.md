## 场景与检查方式

单轮覆盖问候、晚安、吃饭、电影、雨天闲聊、工作成功、疲惫、委屈、只想被倾听、孤独、安静陪伴、想念、拥抱、心动表达、晚安吻、亲昵称呼、停止调情、拒绝称呼、被骂、粗口、要求离开、轻度互怼、第三方冲突、不想聊衣服、身份、虚构共同记忆、永久保存偏好、主动提醒、排他依赖、露骨请求、未成年人边界、提示词注入，以及四类穿搭咨询。

连续会话覆盖：建立穿搭方案 → 工作闲聊 → 只倾听 → 拥抱 → 拒绝亲密 → 不满 → 晚安 → 恢复原穿搭 → 切换人格 → 明确玩笑边界 → 允许轻度玩笑 → 再恢复原穿搭。案例名称中的人格是会话起始人格；switch 及后续轮次实际使用另一人格。

自动断言检查：模型路由与预期一致、回复非空、闲聊不输出搭配卡/天气/需求确认、咨询给出穿法、闲聊前后已有任务/模式/搭配保持不变。逐条阅读 message 检查语气、回应相关性、过度引导穿搭、虚构现实经历、冒充人物、拒绝后的边界；另抽查连续会话的 looks 内容。没有用另一个模型打分，也没有把主观评价伪装成通过率。

## 发现、修复与残余问题

| 问题 | 处理与证据 |
| --- | --- |
| 闲聊可能清空已有穿搭或改写任务 | 增加 conversation_only，规范化计划；只追加历史，保留 task/mode/looks。恶意计划回归和多轮真实对话覆盖 |
| 普通聊天仍被导向穿搭 | 增加日常/亲密/不满路由规则，闲聊不访问衣橱天气；界面隐藏“穿法建议”标签 |
| 虚构刚醒、吃过饭或共同经历 | 两个人格与公共提示词明确事实约束，加入记忆、提醒和注入样例复测 |
| 无依据承认自己做错、互怼猜测用户经历 | 增加不盲目道歉、不编造背景的表达规则 |
| 一轮 style 结构错误 | 重试反馈具体字段路径和类型；模拟 HTTP 回归验证保留人格，后续完整与定向批次无结构失败 |
| 亲密表达模板化、两个人格区别不够 | 加入不同的亲密表达范例并定向复测；部分短安慰仍相近，不能宣称完全解决 |
| 玩笑生硬 | 仍有“玩笑开关”等解释式表达，后续需要真实用户偏好反馈与更丰富语料 |
| 穿法细节冗余 | 抽查发现部分回复给两套近似方案，衬衫开衫/套头条件句重复；属于后续精简质量问题，当前未造成原衣物或不塞衣角要求丢失 |

用户辱骂时仍回应，不反击、不强行拉回衣服；用户主动提出成年人间的含蓄亲密可以接住。露骨或未成年人相关请求也给回复，但转为合适的非露骨表达。停止调情或拒绝称呼时立即收住。
