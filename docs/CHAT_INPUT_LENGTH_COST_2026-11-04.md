# 七档用户输入长度的闲聊成本

2026-11-04 用户澄清：10、20、50、100、200、500、1000 字指用户输入，不是模型回复长度。模型自然回复，不设目标字数。这里按 Unicode 字符计数，包含标点；回复另计换行。

本次为轻量单调用实验，使用当前配置的真实文字模型 `doubao-seed-2-1-pro-260628`、冷静可靠角色提示、虚构称呼与日常闲聊。七档独立请求、没有历史，不查衣橱／天气、不写用户资料；未修改正式 App 路由。temperature=0.3，thinking disabled，输出安全上限 1800 token，七次均正常 stop，未触及上限。

七次合计 ¥0.057192。费用按实际 usage 与[火山方舟官方在线定价](https://docs.volcengine.com/docs/ark/model-pricing?lang=zh)测算，普通输入／缓存输入／输出每百万 token 分别为 ¥6／¥1.2／¥30。公式为 `((输入-缓存)*6+缓存*1.2+输出*30)/1000000`。未核对账户折扣或实扣账单。各档一次，不代表长期均值；本次均低于 ¥0.05，不表示正式完整链路已经达到该成本。

误测说明：此前误按回复目标长度进行了 18 次调用，参考费用 ¥0.170454；未混入本次七档结论，工作簿单独列明。合计本轮 25 次真实文字调用 ¥0.227646。此前其他轮次实验见原有成本报告，不在此重复汇总。

交付 Excel：`outputs/chat-cost-20261104/闲聊七档成本实测.xlsx`，包含费用对比、完整用户输入与模型回复、前序误测费用；单价可改，费用为公式，千次费用仅为按样本线性推算。字符断言、usage 核算、七行费用独立对照、改价重算、公式错误扫描及三表渲染检查已完成。

阅读原文发现的质量限制：100 字输入的回复自行增加了“还能多躺两分钟”的例子；500 字输入的回复出现没有天气依据的“等天凉快些”。这些回复保持原样以便审核，成本测试不代表角色表达／事实约束完整验收。纯轻量流程尚需意图分流、安全边界、连续上下文与六角色回归后再考虑接入。
