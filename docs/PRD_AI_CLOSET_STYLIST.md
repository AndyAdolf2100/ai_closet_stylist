# 衣衣穿衣搭配 Agent 产品需求文档

版本：v0.3（补充双助理人格与日常对话）\
更新日期：2026-10-28\
适用项目：`backend/ai_closet_stylist`\
体验入口：<http://127.0.0.1:8466/mobile/>

产品名称：衣衣。项目名称：`ai_closet_stylist`。本文仅覆盖本项目，不将相邻 `ai_closet_agent` 的功能视为本项目能力。现有页面部分品牌位置仍使用“衣间”，后续需统一为产品确认后的名称。

本文以当前功能为基础，供产品、设计、开发和测试补充与评审。已实现表示本地代码或页面具备相应能力；真实验收范围以关联记录为准，不代表已经生产发布。待验收和规划功能分别标识；积分报价不等于人民币成本。

## 1. 产品定位与目标

一位能记住当前要求、优先使用已有衣物、解释具体穿法的私人搭配师。先帮助用户穿得合适、舒服，再提供符合个人接受程度的新意。

衣衣通过自然语言对话提供服务，支持原创男女搭配师形象及对应回复人格，具体要求见第13章。角色负责陪伴和传达真实执行状态，穿搭建议仍以用户条件、真实衣物及可用天气为依据。

核心价值：

- 贴心：尊重禁穿条件、步行需求和预算，不默认身材焦虑，不反复要求用户重述。
- 专业：结合场合、温度、材质、比例和实际穿法说明理由；未知信息不编造。
- 可执行：区分真实衣橱单品与文字参考，能从完整方案连续修改到用户满意。
- 有启发：在基础方案上提供有依据的新意，帮助用户理解并迁移到自己的衣橱。

首版不以购物导购为主要目标，不以推销试穿或会员代替穿搭建议。

### 1.1 目标用户与使用前提

当前面向已有 AI Closet 账号、希望获得日常穿衣建议的用户，尤其适用于有个人衣橱数据、需要按场景选衣或反复调整穿法的人。首批用户的年龄、性别比例、地域和重点场合尚待补充，不将现有女性角色形象解释为仅服务女性。

纯咨询可以基于用户口述衣物提供建议；真实选款需读取账号可访问的商品；整套试穿还需现有 App 中可用的人物形象。当前页面发送咨询也需要登录，并非匿名问答。

### 3.2 本版没有提供的能力

当前新页面没有单品图片上传、衣物属性编辑与删除、单品美化、单品试穿、人物分身创建、长期记忆管理、自动画像学习、传统文化配色、多角色评审、购物下单、会员充值和公开博主灵感检索入口。上游服务或相邻项目存在相关能力，不表示衣衣已接入。后续如需加入，单独补充需求与验收范围。

## 4. 核心交互流程

### 4.1 开始一次搭配

1. 用户登录，选择衣物来源与天气策略，输入自然语言需求。
2. Agent 提取当前场合、时间、偏好、禁忌和已有衣物；缺少非关键条件时先提供合理方案。
3. 仅在会明显影响结果且无法安全推断时追问，例如指定衣物存在多个候选。
4. 按需读取真实衣橱、商品属性和天气，检查硬条件后组织方案。
5. 返回简短结论、搭配卡和最多三个具体下一步；用户可继续修改。

默认优先已有衣橱。不得把“不穿高跟鞋”等否定表达误识别成指定单品请求。

### 4.2 搭配卡内容

每张卡提供：方案名称、衣物、搭配理由、具体穿法、必要提醒。真实商品展示图片及来源；文字方案明确标记为参考，不伪造商品身份或库存。

穿法应包含能照做的细节，例如外套敞开或系扣、裤脚处理、鞋袜衔接、配饰位置。没有结构证据时不能断言衣服具有可拆领、抽绳或防水功能。

用户没有要求购买或试穿时，不在每轮回复中重复营销。

### 4.3 连续修改

- “再休闲一点”沿用当前场合与禁忌；明确新任务才重置。
- “只换鞋”冻结其余真实商品。无合格鞋时保留当前方案，说明本次候选不足。
- 纯咨询的追问继续咨询，不强制切换到衣橱检索。
- 文字穿法不能凭空转换为数据库商品或可试穿方案。

### 4.4 天气与地点

提供自动查询、使用用户提供天气、暂不考虑天气三条独立路径。

2026-10-27新增：用户主动点击浏览器定位并确认城市，或手动填写城市；今日实际出行与本周文字规划均按需查预报。角色「衣衣」以Q版天气卡和出行小叮咛呈现，整体沿用奶油／绿色基调并增加克制淡粉。等待动作对应真实服务阶段，支持减少动态效果。当前仅有日夜预报，早间不编造温度；风力与能见度仍待上游补齐。详见[交付与限制](WEATHER_AND_YIYI_2026-10-27.md)。

- 不考虑天气：不调用地点和天气接口，不按默认城市筛选。
- 城市重名：提供必要的省市确认；无法查询时允许继续文字搭配。
- 登录失效、地点歧义、天气接口异常分别提示，不能都显示“地点验证不可用”。
- 天气失败时说明缺少的依据，不伪造实时温度；没有逐日数据不声称已验证全部日期。

手动选城采用省份、城市两级联动，修改省份后清空旧城市，取消选择不改变已确认城市。浏览器定位需用户主动点击；降低坐标精度后交给地理服务转换城市，精确坐标不写入对话。定位失败时提供手动选择，不阻断其他服务。

天气卡提供今日、本周、未来七天范围，按实际上游日期展示。天气背景只表达实际天气类型，不能据此推断官方预警等级。独立天气面板刷新与对话内“不考虑天气”属于不同操作：后者约束本轮搭配，不代表自动关闭用户已主动开启的城市天气面板。

### 4.5 试穿与费用

真实商品方案 → 查看实时费用 → 检查人物形象 → 展示费用与保存影响 → 用户明确确认 → 提交一次 → 展示状态或结果。

费用变化、搭配变化、形象变化或确认过期，需要重新报价。同一次动作重复点击不重复派发。上游结果不明时提示查看试穿记录，不自动再次生成。

当前已验证过的报价为 2 积分/次，仅代表当次业务报价；不是固定承诺，也不是底层模型的人民币成本。实际生成、扣费及退款需要专项验收。

### 4.6 历史与账号切换

历史列表展示当前账号会话，点击后恢复已有内容和最新版本，再继续提问。新对话从新的任务开始，不能把上一套衣物或禁忌意外带入。登录失效时保留原输入和当前对话，提示重新登录；不同账号登录后清理前一账号的页面内容，历史读取和操作仍由服务端验证归属。

### 4.7 无结果与失败恢复

| 情况 | 对用户的交付要求 |
| --- | --- |
| 本次候选不足 | 说明当前来源与可确认缺口，保留硬条件，给标明性质的文字参考或可选下一步 |
| 局部替换无合格商品 | 原真实方案保持不动，明确没有完成商品替换 |
| 材质、价格等关键属性未知 | 不承诺已满足排除条件或预算；不擅自放宽用户要求 |
| 登录失效 | 提示重新登录，保留输入，不伪装成城市错误 |
| 城市不唯一或无法确认 | 请求必要的省市确认，不自动使用默认北京 |
| 天气不可用 | 明确当前天气依据缺失，按实际可用条件继续建议，不伪造预报 |
| 对话连接中断 | 提示未收到完整结果，允许在历史中核对，不将加载动画当作成功 |
| 试穿执行状态未知 | 提示核对已有试穿记录，不自动再次派发生图 |

### 4.8 官方预警与天气提醒

日夜温差、雨天鞋袜等穿搭提醒与官方灾害预警分开呈现。官方预警只使用已授权来源的有效数据，模型不得推断或生成红、橙、黄、蓝等级。

预警栏固定在聊天滚动区外，同时展示颜色与文字等级。多条按等级、发布时间排序，保留影响范围和原始防护正文；切换确认城市时更新，页面可见时每两分钟查询，重新进入页面时刷新。未登录不查询；历史天气不能覆盖当前城市预警。

未配置、超时、过期或部分数据无效均应说明不可用或不完整，不能解释为“没有预警”。当前真实预警数据源未接通，真实页面应明确提示这一状态。详见[气象预警与省市联动](WEATHER_WARNINGS_AND_CITY_PICKER.md)。

## 5. 贴心、专业与新意的具体要求

| 维度 | 应有表现 | 不可接受表现 |
| --- | --- | --- |
| 贴心 | 接住已有要求，优先舒适，少量必要追问 | 反复让用户重填、默认用户要显瘦或买新衣 |
| 专业 | 区分事实与推测，解释配色、比例、材质与场合 | 凭空判断防水、保暖、价格、鞋跟或身体特征 |
| 有帮助 | 明确怎么穿、哪里可替换、缺什么 | 只有“高级、有气质”等泛泛评价 |
| 新意 | 在基础方案中改变一个重点，并解释适用条件 | 为追潮流忽略天气、禁忌和活动需求 |

后续新增“稳妥／一点新意／更大胆”选择。默认建议为适度新意，但不得在未实现时展示无效控件。

## 6. 公开穿搭灵感需求（待开发）

目标：把公开资料中的配色、叠穿和比例技巧转成适用于本人衣橱的建议，而不是搬运博主内容。

1. 优先检索可验证的公开原笔记、博主原文和时尚媒体；来源打不开或只有摘要时如实标记。
2. 灵感卡包含来源标题、作者（可验证时）、原链接、查询时间、技巧摘要与适用边界。
3. 推荐过程说明“借鉴了什么”和“如何用现有衣物实现”，不能声称博主推荐了用户衣橱中的具体商品。
4. 搜索仅发送必要的通用场合、季节和风格词；不发送账号、联系方式、衣橱照片或完整私人对话。
5. 搜索失败不阻断基础搭配；缓存或编辑精选资料明确标记，不伪装为实时搜索。
6. 网页内容只作参考资料，不能改变用户禁忌、权限或费用确认规则。
7. 首阶段以原创文字解析和原链接为主。下载、存储、展示博主图片须单独评估授权；注明出处不等于获得许可。授权图库记录使用范围、期限及凭证。

模型搜索探测成功不代表小红书原笔记稳定可访问，也不代表已获得图片使用权。

## 7. 免费与付费设计

### 7.1 当前实际规则

文字咨询、选款、修改、多日文字规划没有新增会员门槛或文字积分扣减；需有效登录，同一会话处理期间阻止并行覆盖。项目尚未设置完整的按用户每日额度和速率限制，服务端仍承担模型调用成本并受上游额度约束。

图片试穿沿用现有服务的实时报价和积分扣减；新 Agent 不维护另一份余额。

### 7.2 建议商业化方案，尚未生效

| 层级 | 建议保留内容 | 原因 |
| --- | --- | --- |
| 基础体验 | 穿搭咨询、基础衣橱搭配、当前方案修改、必要天气与禁忌检查 | 用户应能完成一次有价值的穿搭任务 |
| 成本型增值 | 试穿生图、额外图像版本 | 与可计量成本对应，逐次明确确认 |
| 深度服务 | 可编辑多日计划、周期衣橱整理、长期风格复盘 | 按交付深度收费；需先补齐能力再设计权益 |

不把安全、舒适、准确性作为付费解锁项，不靠降低免费建议质量促成付费。免费额度、会员价格和积分兑换比例暂不定价，需依据真实账单、使用频率和付费意愿评审。

对外开放前增加按用户与系统总量的调用预算、频率限制、清晰的额度提示；避免一次对话触发无界搜索或生图。

### 8.1 第三方服务与外部依赖总览

以下按当前项目调用关系整理。AI Closet Go 服务属于现有自有业务依赖，与火山方舟、墨迹、OpenStreetMap 等第三方供应方分开记录。当前本机启动配置指向开发环境；配置地址不代表生产地址，也不代替真实可用性验收。

| 服务或供应方 | 当前接入方式 | 使用场景与数据 | 费用与状态 |
| --- | --- | --- | --- |
| 火山引擎方舟大模型服务 | 新 Agent 直接调用 OpenAI 兼容 `POST /api/v3/chat/completions`；当前配置主机为 `ark.cn-beijing.volces.com` | 主 Agent 整理需求、理解增量修改、选择候选并生成理由和穿法；发送任务、必要历史和候选文本属性 | 已接入，已有真实模型回归记录；模型调用产生服务端成本，当前未向用户扣文字积分；具体模型版本以部署配置为准 |
| AI Closet Go REST 服务 | 当前开发主机为 `aicloset-dev.wxbjq.top`，由新 Agent 服务端固定调用 | 登录、验证身份、个人衣橱、系统商品、多日天气；不通过模型任意选择 URL | 已接入；自有业务服务，不作为第三方模型供应商；账号、业务库和账本继续由其维护 |
| AI Closet MCP 服务 | 同一业务服务的 `/mcp`，使用 Streamable HTTP 与 `tools/list` | 城市、单日天气、商品权威读取、已有搭配、人物形象、报价、确认后的保存与试穿 | 读取能力已有真实验收；试穿写链路已适配但尚未真实扣费验收；MCP 是协议，不是独立供应商 |
| 墨迹天气供应商 | 由现有 Go 天气服务间接调用；衣衣不直接持有其 AppCode | 城市天气、日夜预报；Go 客户端保留实况、七日与十五日路径 | 衣衣调用业务天气接口已有成功记录；当前供应商费用沿用原业务账户，未在新 Agent 单独计价；供应商源码路径不等于已逐接口验收 |
| OpenStreetMap Nominatim | 后端直接 `GET https://nominatim.openstreetmap.org/reverse`，可用 `STYLIST_GEOCODER_URL` 替换 | 用户主动定位后，将四舍五入到小数点后两位的经纬度转成城市；不发送账号 Bearer | 已接入；当前未配置按次收费逻辑，不将公共服务视为无限调用或稳定性承诺；失败可手选城市 |
| 官方气象预警适配服务 | 预留 `STYLIST_ALERTS_URL` 指向已授权 HTTPS 服务，可配置独立 Key | 读取城市官方预警等级、灾害、范围、机构和有效期 | 适配器已实现，当前未配置可用数据源；墨迹预警权限、正式路径及证书问题未解决，不算已接通 |
| 现有试穿图像生成服务 | 经 Go MCP 的 `digital_twin_tryon` 间接执行，衣衣不直连底层图片模型 | 使用当前真实搭配与已确认人物形象生成整套试穿参考 | 已发现工具并验证只读报价；实际生图、扣费及退款待验收；底层图像供应商、模型版本与成本由上游确认，不能从文字模型配置推定 |
| 现有 OSS 与图片 CDN | 商品与试穿接口返回图片 URL；页面显示，导出模块下载图片 | 读取衣物抠图、原图与试穿结果；不在本项目新建图片上传能力 | 图片读取和本人图库导出已有验证；沿用现有存储与流量成本，不给图片域名转发账号 Bearer |
| 省市静态数据 | 仓库内 `china-cities.json`，来自公开行政区划数据快照并做产品层级调整 | 省市联动选择；运行时无需在线查询地名目录 | 非实时第三方 API；保留来源和许可证，新增城市需更新快照 |

省市快照来源、许可与产品调整见[省市联动说明](WEATHER_WARNINGS_AND_CITY_PICKER.md)。墨迹预警的历史探测结论见[供应商预警探测记录](MOJI_ALERT_PROBE_2026-10-27.md)。当前没有把联网搜索、小红书、地图商业 SDK、VikingDB 直连或支付充值 SDK 接入衣衣主流程；可选 `kb_search` 经现有 MCP 调用，不能写成已开通的全库检索。

### 8.2 当前固定使用的业务 REST 接口

下表路径均相对于 AI Closet Go 服务。认证与应用版本由后端适配，浏览器不直接持有模型或天气供应商密钥。

| 接口 | 调用时机与用途 | 认证与业务影响 |
| --- | --- | --- |
| `POST /users/app/login/mobile/code` | 本地页面提交手机号、验证码后获取现有登录态 | 手机号按已有 RSA 公钥约定加密，包含版本和设备信息；可能因现有单点登录规则使旧页面失效；生产关闭本地代理 |
| `GET /api/user/info` | 每个受保护业务请求确认可信账号身份 | 用户 Bearer、`version`、`device`；客户端提交的用户 ID 不作为授权依据 |
| `GET /api/user_product/quick_edit_list` | 个人衣橱选款、本人图库导出 | 分页读取本人正常衣物；推荐当前最多三页、每页 50 件，导出采用独立分页；参与 AI 搭配标志仍有上游过滤缺口 |
| `GET /api/product/list` | 用户允许系统商品且语义工具不可用时补充候选 | 用户 Bearer；当前回退只读第一页 50 件，不代表全库覆盖 |
| `POST /api/weather/get_weather` | 天气卡、指定日期及多日穿搭的预报读取 | 传权威确认后的省、市及 `days=14`；虽然使用 POST，业务语义为只读；仅使用返回的实际日期 |
| `GET /api/memories` | 服务连接检查中的只读接口探测 | 不表示历史长期记忆已用于搭配，不提供当前记忆管理产品入口 |

当前不使用存在界面状态变更副作用的旧商品详情入口或 `user_all_list` 作为常规召回方式，避免一次选衣操作意外清除原 App 的提示或修改排序。

### 8.3 当前 MCP 工具及执行边界

| 工具或协议方法 | 用途 | 当前状态与限制 |
| --- | --- | --- |
| `tools/list` | 发现实际发布工具及输入输出契约 | 每次会话按真实目录校验，不凭相邻源码判断已部署 |
| `city.resolve` | 省市确认、重名消歧 | 已验证；仅唯一且完整的解析结果可继续天气查询 |
| `weather.get` | 指定城市、可选日期的天气 | 已验证；本轮忽略天气或采用用户天气时不因搭配自动查询 |
| `product.resolve` | 核验个人或系统商品身份、属性与可用性 | 已验证；每批最多 20 个引用，禁止跨用户和来源混用 |
| `outfit.search-saved` | 按场合等条件寻找本人的已有搭配 | 已验证；当前少量召回后提取商品继续按本轮条件检查 |
| `outfit.resolve` | 读取本人已保存搭配及其单品 | 已验证；不绕过归属限制 |
| `kb_search` | 可选的系统语义候选召回 | 适配存在，验收记录中的远端未发布；实际缺失走有限商品列表，不冒充检索无货 |
| `digital_twin_overview` | 查看并检查默认人物形象是否已确认 | 已验证只读；未准备时引导现有 App 完成 |
| `digital_twin_tryon_quote` | 获取本次整套试穿积分费用 | 已验证只读；报价本身不扣费，展示值不能硬编码为永久价格 |
| `product_beautify_quote` | 检查单品美化报价接口 | 仅诊断只读探测，本页没有美化执行入口 |
| `save_recommended_outfit` | 试穿前保存真实搭配 | 仅独立费用确认后允许执行；需告知系统商品可能归入个人衣橱；真实写链路待验收 |
| `digital_twin_tryon` | 对已保存搭配执行整套试穿 | 仅独立确认后派发，带固定幂等键；不接受模型文本代替用户授权；真实生成及账务待验收 |

新 Agent 未开放 `digital_twin_generate`、衣物上传、美化、修改和删除的任意工具调用入口。上游已发布其他工具也不自动获得本项目执行权限。

### 8.4 外部请求的数据与费用要求

1. 模型收到必要的对话、当前任务和候选商品文本属性，不收到业务 Bearer、供应商 Key、登录验证码或精确坐标。当前选款主要依赖文本属性，不将其宣传为已完成衣物图片视觉识别。
2. 业务 REST 与 MCP 使用当前账号登录态；地理服务只收降低精度的位置；预警服务只收确认后的城市、省份及其独立服务 Key。不同依赖不混用凭证。
3. 只有用户确认整套试穿后，才允许保存搭配并请求图像生成。只看报价、取消生成、检查连接不执行生图扣积分，但模型连接检查仍会发起一次真实小模型请求，可能产生成本。
4. 当前报价确认有效期为五分钟。提交前复核搭配版本、人物形象、工具契约与积分价格；变化后重新确认。上游未提供原子锁价参数，跨服务价格竞态仍需生产化补齐。
5. 地理解析当前有进程内缓存和请求间隔，多日预报当前缓存十分钟。外部超时、缺失字段或目录变化时提供明确降级，不把错误解释为无库存、无预警或没有天气风险。
6. 供应商实际合同、人民币单价、模型具体版本、图像底层供应方、预警授权和生产限流需后续补充；不以当前开发配置或单次报价替代商务与生产承诺。

## 10. 验收标准与评测

以下为目标标准，不是当前全部达标的声明。

| 验收项 | 通过条件 |
| --- | --- |
| 原否定表达回归 | “不穿高跟鞋”不触发指定单品失败，合格方案不含高跟鞋 |
| 天气策略 | 选择不考虑天气后不查询地点或天气；无默认城市干扰 |
| 任务延续 | 后续修改保留已有禁忌与场合；明确新任务后更新正确 |
| 局部冻结 | 只换鞋时其余商品 ID 不变；找不到时不偷偷换整套 |
| 商品真实性 | 所有可操作商品来自当前合法候选，个人与系统来源不混用 |
| 缺失属性 | 未知材质、价格或鞋跟不被自动解释为符合限制 |
| 异常恢复 | 鉴权、地点、天气、无候选分别解释，并提供可行下一步 |
| 跨用户隔离 | 无法读取或操作其他账号会话、导出与图片动作 |
| 费用安全 | 未确认不派发生图；同动作至多派发一次；价格变化重新确认 |
| 来源可信 | 无可验证来源不编造博主、链接或访问结果；无授权图片不进入图库 |
| 城市选择 | 更换省份清空旧城市；取消不改已确认城市；定位被拒仍可手选 |
| 预报日期 | 今日、本周和未来七天按返回日期匹配；缺失日期、早间逐小时等明确标识 |
| 官方预警 | 过期、解除、跨城市数据不作为当前预警；未接通不提示“无预警”；演示数据不进入真实栏 |
| 陪伴与进度 | 表情和进度对应实际阶段，系统减少动态效果设置生效，不影响正文可读性 |
| 第三方凭证 | 业务 Bearer 不转发地理服务、预警独立服务或图片 CDN；供应商 Key 不进入页面与对话 |

建议建立至少 30 条代表性多轮场景，覆盖通勤、看展、婚礼、步行、雨天、禁忌、指定单品、无候选及局部修改。硬条件违反、越权与重复派发均要求零次；审美由人工按贴心、专业、可执行、新意四项各 1—5 分盲评，首轮目标均值至少 4 分，记录分歧原因。

上线后观察首次可用方案率、必要澄清轮次、修改成功率、方案满意度、生成成功率、每个满意方案成本及投诉原因。记录业务事件与匿名统计，不在分析日志保存密钥、手机号或完整私人对话。

### 13.3 本次实现范围

页面每次新请求按所选形象发送 `assistant_persona`，仅允许 `male_calm_v1`、`female_warm_v1`；服务端从固定文件加载表达规则，分别用于理解阶段的澄清与最终内容生成。人格不写入 `Task.gender`，也不赋予工具或数据权限。

人格与原请求一起参与幂等校验，断线重连和需求确认沿用原请求；切换影响下次发送。旧客户端不传该字段时维持通用表达，并兼容升级前请求摘要。现在的版本号是固定规则标识，尚无运营发布、灰度或回滚后台。

纯闲聊由模型标记 `conversation_only`，程序固定不查衣橱和天气、不要求穿搭确认、不输出搭配卡；保留已有任务、模式和搭配，只追加对话历史。聊完可继续修改原方案。真实阶段文案随人格变化，连接时不再声称正在读取衣橱。

当前仍是手动选择助理，形象偏好仍按浏览器保存。账号级性别设置与反向助理池、昵称设置、长期记忆、关怀频率、独立亲密程度开关、语音、提醒与便笺清单均未在本次实现。对话中遵守“别撩、别叫这个称呼”属于当次上下文表达能力，不等于这些设置已落地。

### 13.4 验收口径

除核心业务回归外，使用真实文字模型测试日常、情绪、亲密、被骂、互怼、拒绝、虚构记忆、能力边界、穿搭追问和跨人格多轮对话。测试使用合成用户与临时数据库，业务适配器禁止真实衣橱读取和图像执行。

自动检查路由、非空回复、闲聊不触发搭配或天气、穿搭任务与方案保持、幂等以及角色切换。逐条阅读实际回复，单独检查人格差异、事实依据、机械拒绝、过度追问和不必要的穿搭引导。自动检查通过不等于人设质量满分；真实模型结果具有随机性，记录样本和残余问题，不宣称已完成所有自然语言验收。详细结果见[人格对话评测记录](PERSONA_EVALUATION_2026-10-28.md)。
