# 积分获取任务页

2026-11-06：H5页面及现有接口已本地实现。用户确认真实发奖、支付完整链路留待iOS接入，不作为当前H5版本阻塞；iOS按实际发布版本管理，可能高于2.0，不擅自固定或修改版本号。本轮为本地与模拟验证，非远端真实领奖／支付验收。

## 页面与入口

- 我的页面账号资料右侧“积分获取 ›”进入二级页；顶部只显示当前六角色之一的来信横幅，配色沿用App主题。
- 展示权威积分余额、每日签到、衣橱里程碑进度及购买积分包／会员提示。
- 提示文案：“还想陪你，多试几套。添一点积分，下一套心动接着来。”两入口统一白色圆角卡片、图标与等宽按钮，充值实心、会员描边。
- “去充值”打开现有积分页签，会员入口打开会员页签；返回时重新读取任务，旧视图不会因销毁而失效。
- 未登录账号卡不再显示右侧“登录衣橱”按钮；头像复用统一登录事件，积分任务页仍保留登录入口。游客不查询奖励或余额。

## 接口与积分边界

- GET /stylist-api/app/points读取积分余额，未知显示“—”，不在本地累加余额。
- GET /stylist-api/app/checkin读取签到状态／历史／奖励配置；明确点击后POST同路径，防重复提交。成功回读状态及余额；回执未知先“刷新确认”，不自动重试POST。
- GET /stylist-api/app/milestones只代理GET /api/milestones并校验current_item_count及tiers字段；已发放显示“已收下”，达标未发放显示“待同步”，未达标复用添加衣物入口。
- 当前H5不调用POST /api/milestones/check。Server源码中该POST会先检测发奖、再读取并标记通知；不能当作只读请求。真实上传奖励闭环由iOS后续接入，不宣称H5已真实验收。
- Server源码发奖门槛为客户端1.6.0，本地配置当前为1.2.0；该差异记录在此，后续按iOS实际发布版本处理，不为了绕过门槛擅改请求版本。
- 不新增邀请、广告、分享或完善资料奖励，不硬编码签到／里程碑额度；不直接写原Server MySQL或向量库。
- 现有H5 SKU购买继续为演示，不创建订单、不扣款、不变更积分。

## 会员入口判断

每次读取GET /stylist-api/app/profile的最新vip_info，并同步已有SKU中心的账号状态：

| 状态 | 标题 | 按钮 |
|---|---|---|
| 非会员／已过期，is_vip=false或0 | 开通会员 | 去开通 |
| 有效会员，is_vip=true或1 | 续费会员 | 去续费 |
| 仅永久会员，无有效时段档位 | 会员权益 | 查看权益 |
| 未读取／格式未知／读取失败 | 会员方案 | 查看会员 |

永久身份与有效时段会员可并存，此时按有效时段显示续费。未知状态不默认判成非会员。所有请求和显示按账号隔离，换号清理旧内容并忽略迟到响应。
