# 架构与执行边界

## 正常对话

```text
已有 Bearer → Go 服务验证身份 → 本地请求幂等／版本预留
 → 主 Agent 整理当前任务与增量修改
 → 普通穿法咨询直接进入造型建议；实际出行文字方案按需查天气
   或按明确选择读取真实衣物、必要天气及保存搭配
 → 硬性要求过滤 → 主 Agent 选款并解释穿法
 → 商品引用、完整结构、冻结位置、预算和禁忌检查
 → 必要时一次有界选款修正 → 保存一轮结构化结果
```

没有递归的多 Agent 评审，没有“用＋衣橱＋服装名”决定意图的关键词门禁。真实商品候选由程序提供，模型不能编造可操作的商品身份。语义理解仍需真实模型验证，不能宣称程序门禁能证明所有审美与自然语言理解都正确。

## 状态与恢复

- 当前任务保留场合、日期、城市、天气策略、身高等用户明确提供的信息、步行、预算、禁忌、现有衣物描述与穿法偏好。
- 非独立新任务采用增量更新。每项变化保留本轮原文证据；引用格式不合格时先内部修复，不把内部格式错误直接推给用户。
- 咨询追问保持咨询；已有文字穿法不会凭空成为数据库商品方案。商品无结果与接口故障分别表达。
- 用户明确要求忽略天气时，不查城市和天气，也不按默认北京筛选。用户提供天气时保持其事实来源；实时天气不写成用户永久偏好。
- 今日实际出行默认查询当天，本周按日期匹配至周日；优先读取真实日夜预报。浏览器定位由用户点击，降低精度后转换城市；精确坐标不入会话。缺少早间逐小时、风力与能见度时明确缺口，不能编造分时实况或无风险结论。参见[天气专项交付](WEATHER_AND_YIYI_2026-10-27.md)。
- 局部修改冻结未指定变更的位置，并权威读回身份。未找到替换时，当前真实方案保持，文字参考另行标识。
- owner 从上游验证，客户端不能指定 owner；本地历史、请求与图片动作均有 owner 隔离。
- SQLite 原子预留、版本与 claim 校验阻止并行覆盖；模型调用不在数据库事务内执行。失效工作进程无法写回覆盖新结果。

## 图像执行

```text
用户点击查看费用 → 核对当前真实搭配和人物形象
 → 获取实时费用并保存快照
 → 用户独立确认
 → 再核对费用、形象、工具契约与搭配版本
 → 原子认领动作 → 保存搭配 → 既有试穿服务生成
```

一次确认仅对应本次动作。重复确认返回既有状态或结果，不重复提交。图像调用使用更长超时；提交后如果连接中断或进程状态不明，不自动调用第二次生图。用户可在现有 App 试穿记录中核对。

限制：现有试穿 API 未提供“按本次报价原子锁定扣费”的参数，新服务只能在提交前复查报价，不能证明跨服务价格变更竞态已消除。现有上游扣费、失败返还与执行恢复需要单独真实验收。首次试点应保持运营价格稳定；生产化前应补充权威报价绑定及执行状态查询，而不是用本地状态代替账本。

## 免费与付费

文字咨询、普通选款和当前任务修改共享同一质量标准。本版没有添加新的会员、充值、套餐或文字额度扣减逻辑。图像成本使用现有积分报价和业务执行，页面先显示真实费用及保存影响，再确认。

一周规划的收费档位、免费额度和价格实验属于产品计划，尚未变成已上线权益。长期画像、记忆写入、复杂旅行计划、人工搭配师、图片修订不在本轮核心交付范围内。

## 当前候选范围

个人衣橱每轮最多读取前三页、每页50件，最终按位置平衡模型上下文。系统语义检索工具如果实际已发布则可召回；当前远端未发布，使用已发布商品列表的有限候选。未知价格、材质、颜色或鞋跟不能伪造为满足硬性要求。

这意味着大衣橱和系统商品覆盖仍有限，需要后续接通受支持的服务端语义检索／按属性分页接口。无结果提示必须限定为“本次候选”，不能声称全库存不存在。
