# 架构与执行边界

## 持久化执行

当前由 LangGraph 编排单个主 Agent，节点、检查点、暂停确认与恢复见 [入门说明](LANGGRAPH_QUICKSTART.md)。本地默认 SQLite，多副本需要共享 PostgreSQL；SSE 订阅断开不取消后台生成，异常死亡后由同一请求的重连恢复已完成步骤。没有独立后台调度器，收费写操作不纳入自动重试。部署参数与限制见 [K8s 部署说明](KUBERNETES_DEPLOYMENT.md)。

## 正常对话

```text
已有 Bearer → Go 服务验证身份 → 本地请求幂等／版本预留
 → 主 Agent 整理当前任务与增量修改
 → 普通穿法咨询直接进入造型建议；实际出行文字方案按需查天气
   或按明确选择读取真实衣物、必要天气及保存搭配
 → 硬性要求过滤 → 风格／场合排序并按槽位保留候选
 → 主 Agent 按简短造型简报选择核心及配套，并解释穿法
 → 商品引用、完整结构、冻结位置、预算、禁忌及原话套数上限检查
 → 仅属性措辞问题先本地修正并重新完整校验；其余必要时一次有界模型修正
 → 保存一轮结构化结果
```

没有递归的多 Agent 评审，没有“用＋衣橱＋服装名”决定意图的关键词门禁。真实商品候选由程序提供，模型不能编造可操作的商品身份。语义理解仍需真实模型验证，不能宣称程序门禁能证明所有审美与自然语言理解都正确。

## 状态与恢复

- 当前任务保留场合、日期、城市、天气策略、身高等用户明确提供的信息、步行、预算、禁忌、现有衣物描述与穿法偏好。
- 非独立新任务采用增量更新。每项变化保留本轮原文证据；引用格式不合格时先内部修复，不把内部格式错误直接推给用户。
- 咨询追问保持咨询；已有文字穿法不会凭空成为数据库商品方案。商品无结果与接口故障分别表达。
- 用户明确要求忽略天气时，不查城市和天气，也不按默认北京筛选。用户提供天气时保持其事实来源；实时天气不写成用户永久偏好。
- 今日实际出行默认查询当天，本周按日期匹配至周日；优先读取真实日夜预报。浏览器定位由用户点击，降低精度后转换城市；精确坐标不入会话。缺少早间逐小时、风力与能见度时明确缺口，不能编造分时实况或无风险结论。参见[天气专项交付](WEATHER_AND_YIYI_2026-10-27.md)。
- 局部修改冻结未指定变更的位置，并权威读回身份。未找到替换时，当前真实方案保持，文字参考另行标识。
- owner 从上游验证，客户端不能指定 owner；本地历史、请求与图片动作均有 owner 隔离。
- SQLite 原子预留、版本与 claim 校验阻止并行覆盖；模型调用不在数据库事务内执行。失效工作进程无法写回覆盖新结果。

## 图像执行

```text
用户点击查看费用 → 核对当前真实搭配和人物形象
 → 获取实时费用并保存快照
 → 用户独立确认
 → 再核对费用、形象、工具契约与搭配版本
 → 原子认领动作 → 保存搭配 → 既有试穿服务生成
```

一次确认仅对应本次动作。重复确认返回既有状态或结果，不重复提交。图像调用使用更长超时；提交后如果连接中断或进程状态不明，不自动调用第二次生图。用户可在现有 App 试穿记录中核对。

限制：现有试穿 API 未提供“按本次报价原子锁定扣费”的参数，新服务只能在提交前复查报价，不能证明跨服务价格变更竞态已消除。现有上游扣费、失败返还与执行恢复需要单独真实验收。首次试点应保持运营价格稳定；生产化前应补充权威报价绑定及执行状态查询，而不是用本地状态代替账本。

## 免费与付费

文字咨询、普通选款和当前任务修改共享同一质量标准。本版没有添加新的会员、充值、套餐或文字额度扣减逻辑。图像成本使用现有积分报价和业务执行，页面先显示真实费用及保存影响，再确认。

一周规划的收费档位、免费额度和价格实验属于产品计划，尚未变成已上线权益。长期画像、记忆写入、复杂旅行计划、人工搭配师、图片修订不在本轮核心交付范围内。

## 当前候选范围

个人衣橱仍每轮最多读取前三页、每页50件；这是覆盖边界，不能宣称全库存搜索。本轮风格与已允许的本人偏好在每槽位截断前参与排序，每槽位最多10件；开启邂逅新衣时保留个人／系统各自窗口。仅在显式开启或经原话核验授权时检索系统参考款，沿用当前按分类、性别召回及软扩大，权威详情不一致的候选排除。无结果提示必须限定为“本次候选”。

风格软偏好不再因某槽位存在同名标签就删除其他全部合规候选；未知标签及基础单品可参与配套。本轮明确要求优先，禁穿、性别、来源及冻结仍由程序检查。造型简报只汇总已知场景、有效风格与匹配候选键，不新增模型调用，不虚构商品属性；主模型负责核心单品与配套关系。套数由Plan提取并逐字核对当轮数量证据，不超过用户明确上限；超量由原有修复步骤同时修正卡片与正文，不直接截断卡片造成文案矛盾。

## 2026-11-06 速度与质量迭代

- 模型HTTP连接在应用生命周期内复用，单次脚本保留自动关闭；角色、资料、图片和Authorization仍按请求传递，不放入共享客户端状态。
- 商品详情以20件分批、单次resolve调用最多3批并发，保持批次顺序与商品身份校验；失败等待同批其他只读调用结束后再退出MCP会话，不返回半个已验证候选池。系统分类查询与多城市天气原有有界并发继续保留。
- 公共规则／schema在角色内容之前，JSON去除格式空格，动态时间放在业务payload最后；不删用户原文或证据。缓存是否命中以模型usage为准，不能将布局调整宣称为固定加速比例。
- 单纯属性措辞缺少证据且选款／结构合格时，先复用已有保守修正器去掉不支持的断言并重跑全部校验；不新增选款，不改冻结或硬性限制。标题、风格与非属性问题保留模型修复，不能为省时跳过校验。
- 评测分开记录生成用时与包含审核的总用时，并保留模型逐阶段耗时、生成usage、缓存token及运行源码哈希；审核调用费用不混作生成费用。各版本失败样本原样保留，本轮真实文字模拟业务结果见[DIALOGUE_QA.md](DIALOGUE_QA.md)。

本轮借鉴同级Agent的核心单品／配套思路、简短造型简报和有界预算；同时参考[延迟优化](https://developers.openai.com/api/docs/guides/latency-optimization)、[简单可组合的Agent工作流](https://www.anthropic.com/research/building-effective-agents)、[上下文工程](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)及[检索后重排](https://www.anthropic.com/research/contextual-retrieval)。这些方法提供设计依据，不证明本项目效果；当前未新增多Agent评审、向量库、图片审美识别或个人衣橱全库召回。
