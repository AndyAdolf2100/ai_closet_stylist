# 无抠图时在浏览器去背景

2026-10-30，PRD-03。真实搭配组合优先读取已存在的抠图；缺少抠图或抠图链接加载失败时，读取原图并在浏览器 Web Worker 内执行 U2NetP 前景分割。处理期间不展示逐件图片和去背景文案；完成后参与整套排版并保存最终透明组合图到OSS，见 `OUTFIT_COMPOSITION_DESIGN.md`。

## 处理与边界

- ONNX Runtime Web 1.20.1＋U2NetP；运行时、WASM 与模型共约 15 MiB，自托管，首次使用才加载；一个 WASM 线程串行推理，避免重复下载和多套同时推理争抢内存。来源、许可和校验值位于 `stylist/static/vendor/cutout/`。
- 320×320 模型输入，原图处理边长最多 1280px，图片文件上限 12 MiB、解码像素上限 2400 万；蒙版按原图比例还原并裁去透明边距。已有透明通道的图片不额外推理，但仍在Worker中统一清理透明蒙版里的主体外残字。
- 归一化蒙版后清除低透明度噪声及细小、与主体分离的前景岛，减少背景品牌字母残留；保留显著的多个主体，避免把一双鞋只留下其中一只。不会识别并抹去衣物面料上的印花／商标，模型有边缘或复杂背景误差，处理失败保留原图。
- 中间单品抠图结果只存本页内存与 Blob URL，不写 localStorage、sessionStorage、数据库或旧衣橱；同账号同图片合并重复工作，缓存最多24件，切换账号／退出／页面离开撤销结果并取消待处理工作。失败不缓存，重新打开组合可重试。
- 同一套组件跟随男女主题变量。PC 详情左右排布、手机上下排布，缩略图横向滚动，长标题自动换行；原图详情仍保留，以便查看真实细节。

## 同源原图读取

部分现有图片服务未提供跨域画布读取所需的 CORS 响应，因此增加只读 `GET /stylist-api/wardrobe/{product_id}/image-source`：

1. 校验登录及合法衣物 ID，通过当前账号的 `product.resolve` 仅解析 `source=user`。
2. 不接收客户端 URL，不允许查询系统商品或访问任意地址；只读取解析结果中的原图。
3. 仅允许两个现有 HTTPS 图片域名及443端口，禁止 URL 用户名／密码、重定向、SVG与非图片响应，下载上限12 MiB、20秒超时。不把账号凭证发往图片域名。
4. 响应为 `private, no-store`、`nosniff`、`Cross-Origin-Resource-Policy: same-origin`。此接口只读原图，不执行模型推理、保存或扣费。

## 验证记录

- `tests/test_wardrobe_image.py`：账号身份／仅个人衣物解析、错误商品返回、URL白名单、非图片／重定向／超大图片、缺少登录及私有响应头。
- `tests/local_cutout.test.cjs`：模型预处理、异常蒙版、脱离主体的背景字母清理、保留成对鞋与连接细节、缓存合并、账号切换的迟到结果拒绝、失败后重试。
- 使用现有本机导出的五件真实原图（衬衫、裤子、大衣、鞋、包），故意清空 cutout 字段，在 Chrome 实际执行浏览器推理并成功组成预览；不是用已有抠图冒充推理。真实衣物及私有预览代码仅在被Git忽略的 `var/real-outfit-preview/`，本机端口8767，不随产品静态素材发布。
- 组合预览已验证桌面及393×852设备模拟；原图来源代理的权限／协议边界通过模拟上游测试，不代表已在生产环境验收。Safari真机、低内存设备、复杂背景／模特上身图待专项验证；显著主体分割不能保证从上身图准确分离指定一件衣服。
- Logo修复后重新在浏览器处理同一组原图并导出，已目视检查衣物外的两处淡字母残影消失；修复图仅保存本机私有目录。13项前端专项、14项后端／资源回归及Ruff通过。
- 未提交、推送或部署；不调用收费图片生成接口。

### 通用性补充验证

本轮使用15件真实原图（衬衫、阔腿裤、大衣、帆布鞋、包、两组凉鞋、乐福鞋、吊带裙上身图、发饰、领带、眼镜、链条包及运动鞋）比较模型初始蒙版与同一通用清理规则，无单品ID、Logo坐标或品牌特判；对比图与结果保存在不提交的 `var/cutout-general-review/`。15次推理均产出可处理蒙版，目视检查保留成对鞋与包链，背景文字残影有所清除。吊带裙上身图保留人物前景，不能据此宣称准确分离指定衣服；小残影清理不能保证去除与衣物连接或面积很大的背景Logo。衣橱既有抠图仅作比较参考，不是人工标注真值；该样本不是覆盖所有衣物的准确率评测。
