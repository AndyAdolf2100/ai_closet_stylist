# 新版App系统配色方案

2026-11-02，PRD-05。用户提供新版App的衣物／搭配／试穿及会员积分截图，希望在男女助理配色外增加「使用系统配色」，仅修改颜色，样式不变。正式第四步已接入开关、即时预览及账号保存，旧资料仍默认跟随助理；独立对照页继续只读。

建议采用「暖白＋品牌黄」：界面以白／浅灰为主，黄色集中用于主要操作，浅奶油承托选中、来信和柔光，文字与装饰使用独立语义色；H5内嵌Agent关键文字用深墨色，次级强调用深金，品牌黄用于按钮、装饰和选中边线。保留既有立绘、信纸、动画、字体、间距、尺寸、圆角、边框宽度及阴影形状。人物／服装图片不加黄色滤镜；成功、失败等语义色单独保留。

## 2026-11-07 H5当前实现

## 色值与使用范围

截图两组页面的主按钮均以 `#FCDA4F` 为主要像素色，以下以此作为品牌黄参考；其余为本方案拟定色，不宣称是App官方设计变量。

| 用途 | 建议色值 | 范围 |
| --- | --- | --- |
| 品牌黄 | `#FCDA4F` | 发送、确认、主操作 |
| 主按钮文字 | `#302B1F` | 黄色按钮上的深色文字 |
| 页面背景 | `#F7F8FA` | 首页、对话主底色 |
| 内容纸面 | `#FFFFFF` | 卡片、输入、主要弹窗 |
| 浅奶油 | `#FFF8DF` | 选中背景、用户气泡、签到及柔光 |
| 深金 | `#85620F` | 图标、细线及既有装饰 |
| 明确选中边线 | `#B48A14` | 选择控件、焦点和选中边界 |
| 正文 | `#2D2F33` | 标题与正文 |
| 次级文字 | `#73767D` | 辅助说明，不用于弱化关键费用 |
| 分隔与边框 | `#E8E9EC` | 既有边线及分隔 |

亮黄色不直接承担全部文字颜色。计算所得：白字／品牌黄对比约1.37:1，深色按钮字／品牌黄约10.25:1；深金／白色约5.60:1，次级文字／白色约4.55:1。这是色对的计算，不代表全站无障碍已验收。

不建议把会员页的大面积黄色光效搬到全部对话区。截图的功能详情页仍然以白底承托衣物与试穿照片；爱搭衣橱沿用这一层次，重点使用品牌黄，减少与服装颜色的竞争。原有奶油信纸／透明角色背景可替换为浅奶油，保留乙游气质。

## 当前选择与保存规则

在第四步「陪伴的模样」、男女图片组上方放置对齐的「界面配色」栏，右侧用「跟随助理／系统配色」二选一胶囊切换，替代最初悬在右侧的复选框。使用同名单选按钮组，支持方向键、可见焦点及至少44px点击高度；保存时整组禁用。它是配色偏好，用户性别和助理人格仍各自独立。

- 选择「跟随助理」：使用当前所选助理的原有绿／粉或雾蓝配色。已有资料缺省为此模式，不静默覆盖老用户选择。
- 选择「系统配色」：男女助理均使用相同黄白界面；之后换助理仍保留系统色，人物、头像、人格与动画继续跟随助理。
- 切回「跟随助理」：恢复当前助理的对应配色；再次点击已选的「系统配色」保持选中。
- 返回／取消设置：恢复打开前的助理与配色；保存成功后按账号归属持久化，失败保留草稿，切换账号丢弃迟到响应。

「系统」在本需求中指App品牌配色，不是操作系统的自动深浅色。

## 实现核对与边界

当前 `CompanionProfile` 增加独立 `color_scheme: companion | system`，默认companion，旧JSON资料无需迁移。沿用已有带身份GET/PUT和本项目独立资料表持久化；owner仍由身份校验确定，客户端不能指定归属。保存其他偏好继续保留配色字段。

`appearance.js` 保留data-stylist-gender用于原角色视觉及排版，独立data-color-scheme控制颜色。`companion-settings.js` 在第四步即时预览，预览快照同时包含角色和配色；原子保存、失败保留、取消恢复和换号隔离沿用原流程。新CSS只覆盖颜色属性；配色选择使用紧凑二选一操作行，每项至少44px高，原角色卡片样式保留。

`system-colors.css` 为正式页面与只读对照的共同色板；对照样式通过import引用同一文件，避免两套颜色分叉。首页、设置、对话、天气、试穿、手记、签到、偏好、通知及完整来信接入共用变量／语义色。主要流程已验；尚未对每个历史卡片或真机逐项完成视觉验收。

配色不参与模型语义：计划及生成的companion_profile上下文排除color_scheme，Store请求摘要也排除该字段，切换配色不使同一请求变成新任务；旧资料请求摘要的兼容测试通过。不新增选款、上传、收费或自动发送行为。
